代表作品个人项目 · 2026

竣工资料检查器（AI 辅助验收）规则 + 检索 + LLM 疑似复判
问题
一套 220kV 线路资料 669 份文件，送审前 2–3 名资料员要翻 1–2 天；缺项靠经验、无留痕，漏一份就返工。
做法
把归档范围拆成 251 个检查点：规则和检索先找候选，只有 0.40–0.62 的疑似带交给大模型复判；输出“疑似 + 原文依据”，人确认、人签字。拒绝“自动判真伪”。
结果
单次 18 分钟出缺项清单（另人工复核 8 分钟）；项目A F1 74.7%（P 90.6 / R 63.6）；跨项目验证降 12.9 点，据此把“每项目重新校准”写进上线门槛。

我能承担的三件事对应 BA / PM / QA

需求与验收标准

  • 3 场一线访谈（资料员 / 项目经理 / 监理），把“帮我检查”拆成 Given/When/Then
  • 拒绝不可验收的需求，留下书面理由；范围变更走确认
  • 写 PRD、验收标准、异常与失败兜底文案

评测、阈值与成本

  • 251 个检查点；候选池三路合并，避免只测系统擅长的
  • 阈值曲线、跨项目验证、消融与 50 条错误分类
  • 三口径幻觉评测（n=15）；token 成本估算，明确“估算非账单”

系统验证与放行

  • 功能 / 异常 / 性能 / 兼容 / 安全测试矩阵
  • 8 条 bug 台账：P0/P1 全闭环，won't fix 有理由，待回归不冒充关闭
  • 1 人 3 任务 UAT；结论写“有条件放行”，不写“成功上线”

交付与跨职能

  • 能和算法对齐指标口径，和前后端对齐失败兜底，和业务对齐验收
  • 90 天交付推演：立项 → 进场 → 校准 → 试点 → 验收 → 移交
  • 先定“怎么发现变差”，再谈发布；回滚条件写死

三个可核对的事实不是“我很努力”

数字有底稿：251 个检查点的逐条预测汇总成阈值曲线；访谈、UAT、bug 都有独立记录。
错误有分类：50 条错误拆成 5 类，不是只报一个 F1；知道系统会怎么错。
边界有文字：不判真伪、不替代签字、不承诺召回；跨项目不直接搬阈值。
估算不冒充实测：token 成本、13 人时对比、单次 18 分钟，都标了 n=1 或“估算”。
主动说明：这是个人自建项目，不是公司项目；UAT 只有 1 人、评测为单人标注、幻觉样本 15 条、效率对比是单次 n=1。这些限制决定了它现在只能做“辅助自查”，不能做“自动判定”。也正是它们，构成了“有条件放行”的理由。
